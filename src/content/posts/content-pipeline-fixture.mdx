# MDX 语法指南

MDX 让你在编写熟悉的 Markdown 的同时，可以在普通 Markdown 不够用的地方添加组件和 JavaScript 表达式。本指南介绍了在内容驱动的 Astro 站点中撰写文章时最有用的语法。

:::note[什么是 MDX？]
`.mdx` 文件仍然是 Markdown 文档。标题、列表、链接、图片、代码块和其他 Markdown 语法继续可用，而导入、组件、JSX 和表达式作为可选扩展提供。
:::

## Frontmatter

每篇文章都以 YAML frontmatter 开头。它定义了文章页面、列表、搜索结果和订阅源使用的元数据：

```yaml
---
title: 我的 MDX 文章
published: 2026-08-08
description: 文章预览中显示的简短介绍。
tags: [Markdown, MDX]
category: 指南
draft: false
---
```

Frontmatter 应专注于元数据。导入和 JavaScript 声明应放在结束的 `---` 分隔符之后。

## 标准 Markdown

MDX 文章的大部分内容应保持普通 Markdown。这使源代码易于阅读，并为 RSS 和 Atom 阅读器提供有用的静态版本。

```markdown
## 一个章节标题

- 一个列表项
- **粗体文本**和*强调文本*
- [一个普通链接](https://example.com/)

> 引用块仍然是引用块。
```

## 导入和使用组件

MDX 可以在顶层导入 Astro 组件，并直接在文档中使用它们。组件名称必须以大写字母开头。

```mdx
import Notice from "../../components/Notice.astro";

export const message = "属性可以来自 MDX 表达式。";

<Notice label={message} />
```

以下面板是本文渲染的实时组件：

<ContentPipelineFixture label={componentMessage} />

将组件用于可复用的界面元素或结构化内容。普通段落优先使用 Markdown，以保持文章的可移植性和可读性。

## JavaScript 表达式

顶层 `export const` 声明可以为文档准备值。使用花括号插入 JavaScript 表达式：

```mdx
export const topics = ["组件", "表达式", "扩展 Markdown"];

本指南涵盖 {topics.length} 个主题：{topics.join("、")}。
```

此实时表达式计算了 {topics.length} 个主题：{topics.join("、")}。

表达式在构建期间应是确定性的。仅限浏览器的 API（如 `window` 和 `document`）应放在组件脚本中，而不是 MDX 模块体中。

## Wiki 链接

行内 Wiki 链接指向另一篇文章，同时保持句子的可读性。例如，继续阅读 [[guide|内容指南]]。

独立的 Wiki 链接会显示为带有可用元数据和封面图片的文章卡片：

[[guide]]

```markdown
阅读 [[guide|内容指南]] 了解更多详情。

[[guide]]
```

## 数学公式与化学方程式

行内数学公式使用单个美元符号，而展示公式使用一对。`mhchem` 扩展也支持化学方程式。

爱因斯坦的质能方程为 $E = mc^2$。

$$
\int_{-\infty}^{\infty} e^{-x^2}\,dx = \sqrt{\pi}
$$

化学反应可以写作 $\ce{H2O + CO2 -> H2CO3}$。

```markdown
行内：$E = mc^2$

展示：$$\int_0^1 x^2\,dx = \frac{1}{3}$$

化学：$\ce{H2O + CO2 -> H2CO3}$
```

## 图片与说明文字

图片的 alt 文本为辅助技术描述图片。Markdown title 属性会成为可见的说明文字，可选的 `w-N%` 标记控制宽度。

![一个正方形演示图片 w-60%](/images/demos/image-grid-demo/square-1.webp "由 Markdown 图片 title 生成的说明文字")

```markdown
![描述性 alt 文本 w-60%](./image.webp "可见的图片说明文字")
```

有效宽度范围为 `w-1%` 到 `w-100%`。当图片应使用正常响应式宽度时，省略该标记。

## 内部链接和外部链接

使用配置的站点源的相对链接和绝对 URL 被归类为内部链接。指向其他源的链接会收到主题配置的外部链接属性。

- 使用相对站点 URL 访问[关于页面](/about/)。
- 与[外部参考](https://example.com/reference)进行对比。

内部内容请使用相对路径。外部源（如 https://example.com/）由主题单独分类。

## 编写可移植的 MDX

文章页面、RSS 和 Atom 共享相同的内容管道。交互式脚本会从订阅源中移除，但组件、提示框、Wiki 链接、数学公式、代码组和图片产生的语义 HTML 仍然可读。

为确保输出可靠：

1. 将主要说明保持在 Markdown 中。
2. 为图片提供有意义的 alt 文本，为组件提供语义 HTML。
3. 避免在顶层表达式中使用浏览器全局变量。
4. 确保在客户端 JavaScript 运行之前有用信息可见。
5. 发布前运行 `pnpm test`、`pnpm check` 和 `pnpm build`。

MDX 最适合作为 Markdown 的扩展——而非替代品。从纯内容开始，只在表达式和组件能让文章更清晰或更可复用时才引入它们。
